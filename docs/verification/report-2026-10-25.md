# Filter verification — round 1 (2026-10-25)

Method, in one paragraph: two unedited Fujifilm RAWs (CC0, raw.pixls.us —
X-T3 indoor product shot, X100V backlit landscape) were rendered to neutral
sRGB (LibRaw via rawpy: as-shot WB, default gamma, no auto-bright — see
`tools/render_test_images.py`), then every look was applied with the real
CLI (`tools/verify_filters.py`). Raw numbers: `numbers-2026-10-25.md`;
contact sheets: `sheet-AFXT2720.jpg`, `sheet-DSCF0733.jpg`.

## What passed

- **Engine fidelity.** CLI output vs an independent numpy trilinear
  implementation of the same .cube files: mean absolute error ≈ 0.5/255 on
  every sim and image — pure u8 quantization noise. The Rust engine applies
  exactly the LUT data it is given.
- **Sim character.** All directional assertions on both images: Velvia
  saturates more than Provia, Provia more than Classic Chrome; Eterna is
  flatter than Provia; Bleach Bypass is the least saturated. The imported
  data behaves like the simulations it names.
- **Banding.** Sky unique-color ratios 0.72–0.99 vs neutral (Bleach Bypass
  0.486 is its intended desaturation); no visible banding in the sheets.
- **Recipe layer works directionally** in 3 of 4 spot checks (Provia Natural
  desaturates hard as its color −4 demands; Docu Classic Chrome tracks its
  base).

## Findings (the point of verifying)

1. **The base LUTs over-cook contrast on an already-rendered image.**
   Upstream's "assumes linear-contrast input" caveat is real and measured:
   on the backlit landscape (neutral render already 4.9% crushed blacks),
   Velvia crushes 32.0% of pixels to black, Pro Neg Hi 29.0%, Classic
   Chrome 26.5%, Provia 13.5%. In-camera, the sim's curve *is* the render
   curve applied to linear data; on top of a gamma render it double-applies.
   The LUT data is faithful — the input conditioning is the open problem.
   Round 2 experiment: apply to a flat/linear render and compare.
2. **The v0 tone model (additive lift) is too crude at extremes.**
   Kodak Vision3 500T (highlight +4) clips 23.6% of highlights on the
   indoor shot; Docu Classic Chrome (highlight +1) clips 7.7% vs 0.8% for
   its bare base. And the round's one FAIL: Vision3 500T did not raise
   mean saturation on the dark landscape (0.308 vs Eterna 0.316) — the
   additive shadow lift (+3) dilutes measured saturation on dark frames.
   Engine v1 should replace additive lift with a curve-shaped tone op.
3. **Corpus gaps**: no skin tones / portraits yet, and no SOOC-JPEG ground
   truth pairs (RAF + in-camera JPEG of the same frame) — so sim *accuracy*
   in ΔE terms is still unmeasured; round 1 establishes engine correctness
   and behavioral sanity, not colorimetric truth.

## Reproduce

```sh
tools/fetch_test_images.sh          # CC0 RAWs into tests/images/src/
uv run --with rawpy --with pillow python tools/render_test_images.py
cargo build --release -p openfuji-cli
uv run --with numpy --with pillow python tools/verify_filters.py
```

## Round 2 addendum (same day): input conditioning — hypothesis rejected

Three arms on both images (full numbers: `numbers-round2-2026-10-25.md`,
sheet: `sheet-round2-DSCF0733.jpg`):

- **B (linear render → LUT → sRGB encode) FAILED its pre-set bar.** It cut
  Provia's crush by 84% but made Velvia *worse* (+43% crush, mean
  saturation exploding to 0.61 with a garish purple sky) and broke the
  saturation ordering (Provia fell below Classic Chrome). Per-sim
  inconsistency = the cubes were not baked for scene-linear input.
- **A (gamma render) keeps perfect sim character** — the cubes expect a
  gamma-encoded input. Part of round 1's crush is also our austere test
  render (a backlit frame with no shadow recovery); on the normally
  exposed indoor shot, arm-A crush is a mild 1.8–6.0%.
- **C (50% blend) uniformly halves the crush while keeping identity** —
  so the mitigation is a strength knob, not a colorspace change. The
  engine now has `strength` on the LUT stage (default 1.0); guidance:
  0.7–0.85 for contrast-heavy sims on contrasty inputs.

Still open: ground-truth ΔE vs SOOC JPEG pairs (the real arbiter), a
portrait/skin-tone corpus, and the curve-shaped tone model for engine v1.
